# 資金流向觀測台

依手寫清單建置：匯市、債市、股市、商品、國家與公司現金流、VIX，從 1995 年開始做 30 年關聯研究，另有「鉅亨每日」分頁每天匯入鉅亨網新聞與報價並自動標註重點。

**線上 demo：https://ahhshiba.github.io/global-flow-dashboard/** （公開示範版，每天自動更新）

本機打開 `dashboard.html` 就能看（單一檔案，資料已內嵌；字型需要網路，離線會退回系統字型）。

## 指令

```bash
python3 gfd.py all              # 需要時更新歷史（快取 >7 天）→ 分析 → 今日鉅亨 → 產出 dashboard.html
python3 gfd.py history          # 強制重抓 30 年歷史並重算分析（約 2–3 分鐘）
python3 gfd.py analyze          # 只重算分析，不連網
python3 gfd.py daily            # 匯入今天（台北時間）的鉅亨網資料
python3 gfd.py daily --date 2026-09-12
python3 gfd.py daily --backfill 5
python3 gfd.py build            # 只重新產出 dashboard.html
./run_daily.sh                  # 給排程用，log 寫到 logs/daily_YYYYMM.log
```

只用 Python 標準函式庫與 numpy，不需要安裝其他套件。

## 發佈到 GitHub Pages

- 原始碼在 `main`，網頁在 `gh-pages` 分支（每次部署都是**單一 commit 強制覆蓋**，所以 2 MB 的 HTML 不會天天累積在 repo 裡）。
- `python3 gfd.py build --public` 產生 `docs/index.html`：和本機版相同，但**新聞只留標題與原文連結、不含摘要**，避免公開轉載鉅亨網內文；頁尾會標示這是公開示範版。
- `./deploy_pages.sh` 把 `docs/index.html` 推上 `gh-pages`；`run_daily.sh` 每天更新完會自動呼叫它，所以 demo 跟著本機一起更新（電腦關機那天就不會更新）。
- 推送用 `gh` 的 git credential helper，不需要另外存 token。要停止公開更新：刪掉 `run_daily.sh` 裡呼叫 `deploy_pages.sh` 那段，或在 GitHub 設定關掉 Pages。
- `data/`、`logs/`、`docs/` 都不進版控，repo 只有原始碼（19 個檔案）。

## 事件衝擊鏈怎麼算的

回答「某件事發生後，兩週到兩個月內錢往哪流」。用**日線**（月資料做不出兩週的尺度），事件是**真的發生過的事**，不是價格門檻。設定在 `gfd/config.py`（`SHOCK_EVENTS`、`CASCADE_*`），量測在 `gfd/cascade.py`，日線存在 `data/raw/daily_cascade.json`（不進版控）。

43 個標的分五層：上游原物料與能源價格 → 中游能源與資源股 → 中游工業、運輸與石化鋼鐵（含長榮、陽明、中鋼、台塑、台塑化）→ 下游終端需求與科技股（含日經、DAX、富時）→ 資金面利率匯率避險。

### 1999 年以前的事件：代理序列

ETF 與期貨大多 1999–2000 年才有日線，所以 1980–1999 的事件用**代理序列**接在前面（`CASCADE_PROXY`）：只取代理在主序列開始日之前的報酬，接點以主序列第一天的價位對齊，接點之後完全是原序列。

| 標的 | 代理 | 起始 |
|---|---|---|
| WTI 原油 | 美國能源資訊署 WTI 現貨日價（網頁週表解析） | 1986-01 |
| 黃金、白銀 | 倫敦金銀市場協會（LBMA）定盤價 | 1968 |
| 台灣加權 | 證交所 FMTQIK 每日加權指數（快取在 `data/raw/twse_taiex_hist.json`） | 1990-01 |
| 那斯達克 100 | 那斯達克綜合指數 | 1971 |
| 能源、原物料、運輸、零售、必需消費、科技、半導體、公用事業、金融股 | Fidelity Select 產業基金**還原淨值**（未還原的話配息日會假跌） | 1981–1986 |
| 金礦股 | 費城金銀礦業指數 ^XAU | 1983-12 |
| 長債、高收益債 | Vanguard 長期公債基金、高收益公司債基金 | 1986／1980 |

沒有代理的（銅、穀物、天然氣、個股、日圓、新台幣）在早期事件中就是缺資料，頁面會寫「43 個標的中只有 N 個在當時有資料」。代理與原標的不是同一個資產（例：Fidelity 半導體基金 ≠ 費城半導體指數），明細逐筆標註。

**傳導順序是量出來的，不是假設的**：

1. 先判斷有沒有**實質反應**：事件後 42 個交易日內，最大累積變動要超過該標的自身 2σ×√天數（σ 取事件前 60 個交易日的日波動）。沒有就標「無實質反應」，不給速度。
2. 有反應的才算**傳導速度**＝累積變動達到「最大反應一半」的那一天。上游通常幾天就走完，下游會拖。
3. 另外記錄事件前 10 個交易日的變動（看有沒有提前反映）、兩週／一個月／兩個月的變動。

### 實際量到的例子

- **俄烏入侵（2022-02-24）**：WTI 原油與小麥第 5 天走完一半（峰值 +29.5%／+30.4%）→ 銅、玉米第 6 天 → 天然資源股第 7 天 → **台積電與台股第 8 天**（兩個月 −17.2%／−10.2%）。
- **Abqaiq 油設施遇襲（2019-09-14）**：38 個標的只有 4 個有實質反應——原油與**台塑化**都在第 1 天（+13.7%／+7.2%），利率與台積電要到第 14～16 天。
- **雷曼破產（2008-09-15）**：利率第 1～3 天先動，商品與股市第 15～16 天才走完一半。

### 和「平常」比，並做多重檢定

分類彙總與類型比較的每一格都附**無條件基準**＝該標的全部歷史中任意一天起算同樣天數的中位數與上漲比例（S&P 500 平常一個月就有 64% 機率上漲、中位數 +1.24%），否則長期上漲的資產在任何事件後都像「錢流入」。事件後上漲比例和平常的差異用單尾二項檢定。

**多重檢定的結果（2026-09-24）**：1,419 格比較中 89 格 p≤0.05；把每個事件日隨機移到前後三年內重跑 20 次，假事件平均也有 58.6 格過關——**估計約三分之二是運氣**。比較可信的（次數多、p 很小）：

- 金融危機後兩週：原物料股、加拿大 TSX、DAX、S&P 500 下跌（9–10 次中只有 0–2 次上漲，平常 56–60%）；一個月後**黃金上漲 10 次中 9 次**（平常 52%）
- 央行轉向後：10 年殖利率兩個月中位數 +34bp（12 次中 10 次上升，平常 48%），公用事業股與長債下跌
- 戰爭與地緣衝突後兩週：**恆生指數 14 次中 12 次下跌**（平常上漲 54%）

同一類事件的起因不同，4～5 次的類型（選舉、科技、疫情、天災、貿易政策）即使全部同方向也可能是巧合。

### 其他處理

- 同一類裡相隔不到 30 天的事件，彙總時只算較早那個（`CASCADE_DEDUP_DAYS`），避免同一段價格路徑算兩次；單一事件頁會標出 60 天內有哪些其他事件（視窗互相污染）。
- 事件發生在收盤後或週末時，日期填消息公布日，基準自動取那之前最後一個收盤（例：2023-05-25 輝達財測以 5/24 收盤為基準；台股在 DeepSeek 衝擊時休市，基準自動退到 1/22）。
- 2020-04-20 WTI 期貨結算為負值，對數報酬無定義，當天略過。

限制：分類彙總的中位數只能當參考；事件期間常伴隨其他事件，無法分離因果；概略日期的事件已標註。

## 傳導鏈怎麼算的

先寫下經濟學上的假說（例如「日債殖利率上行 → 日圓升值 → 美股下跌 → 費半 → 台股」），每一層都給可判定的觸發條件，再用 1995 年以來的月資料逐段檢定。鏈與條件都在 `gfd/config.py` 的 `CHAINS`，量測在 `gfd/chains.py`。

每段連結量測四件事：

1. **傳導機率**：上游成立後 6 個月內，下游條件跟著成立的比例，對照「任意時點」的無條件基準。
2. **等待時間**：下游條件第一次成立要幾個月（中位數）。
3. **報酬分布**：下游標的在事件後 1／3／6／12 個月的中位數、上漲比例、最糟一次、期間內最大逆行，全部對照無條件基準；p 值用觸發序列循環位移 2000 次的雙尾比例。
4. **先行 vs 追價**：事件當下下游自己前 3 個月動了沒，兩組之後 3 個月的報酬分開比。

事件數是**合併後的獨立事件**（間隔 ≤ 3 個月算同一次），不是重疊月數。

### 目前的結論（每次重算會更新）

- **傳導本身大多成立**：22 段裡 13 段的下游條件出現機率比平常高 10 個百分點以上。最強的是 VIX ≥ 30 → 高收益債下跌（58% vs 平常 21%）、S&P 下跌 → 費半下跌（95% vs 60%）。
- **但「跟著發生」不等於「能賺錢」**：只有 2 段的事件後報酬在統計上站得住（恐慌反轉鏈的前兩段）。其餘與平常沒有明顯差別。
- **「見報就是出場點」不是普世規則**：可比較的 17 段中 10 段是「下游還沒反應時進場」較好，方向大致是恐慌與下跌鏈偏反轉、景氣與上漲鏈偏動能。兩邊事件數都不多。
- 全鏈同時成立的次數通常只有 1～6 次，只能當歷史紀錄看。

這些都是樣本內的歷史統計，沒有做樣本外交易驗證，也沒有計入交易成本與流動性。

## 訊號劇本怎麼算的

回答「出現某個訊號時，錢放哪歷史上比較好」。設定在 `gfd/config.py`（`PLAYBOOK_*`），量測在 `gfd/playbook.py`。

- **前兆**：哪些訊號常在事件前 6 個月出現。同時給**精確率**（前兆出現後事件真的發生的比例）與**召回率**（事件有多少次事前看得到這個前兆），只看其中一個會誤判。
- **期望值＝超額**：事件後報酬中位數 **減掉該資產自己的無條件基準**。不扣基準的話，長期上漲的資產會一路排在前面，那不是訊號帶來的。
- **樣本外**：以 2012 年切成前後兩段，兩段中位數必須同方向才列入。
- **可投資 vs 觀察指標**：VIX、殖利率、利差不能直接買進持有，事件後又常有機械性反應，因此分開呈現。

### 多重檢定：這一步不能省

一次檢定 3,549 組（訊號 × 資產 × 期間），光靠運氣就會撈到一批「有效」結果：

| p 值門檻 | 實際通過 | 運氣預期 | 估計偽發現率 | 加上前後半期一致與幅度門檻 |
|---|---|---|---|---|
| p ≤ 0.10 | 474 | 355 | 75% | 292 |
| p ≤ 0.05 | 268 | 177 | 66% | 187 |
| **p ≤ 0.02（採用）** | **137** | **71** | **52%** | **102** |

**虛無校準**：把事件時點整體隨機位移後，用完全相同的流程重跑 3 次，在「確定沒有訊號」的資料上分別有 37、54、61 組通過全部門檻（平均 50.7）。實際資料留下 102 組（可投資 67 組），所以**估計約一半是運氣**。這個比例是量出來的，不是假設的（先前版本曾用「篩選大概濾掉一半」的假設估成 35%，低估了雜訊）。

**方向與假說相反的結果會自動標記**：例如「日圓 3 個月升值 ≥ 2% → 費城半導體 6 個月超額 +11.1%（p=0.002）」與日圓套利平倉鏈的敘事相反（該鏈預期日圓升值時半導體走弱）。這種結果要嘛是統計假象，要嘛代表這個訊號反映的其實是別的機制（例如日圓升值常伴隨降息預期與美元走弱），清單中以 ⚠ 標示，不要直接照用。

註：這裡刻意不用 Benjamini-Hochberg。循環位移檢定只有約 381 種位移，p 值下限約 0.005，BH 在 3,549 次檢定下會要求 p < 0.00003，那是這個檢定做不到的精度，用了會把「精度不足」誤報成「完全沒訊號」。改用「運氣預期值 ÷ 實際通過數」估偽發現率。資產彼此相關，實際偽發現率可能更高。

所有統計都沒有計入交易成本、滑價、稅負與流動性，也不是投資建議。

## 設定

所有標的、龍頭股名單、危機區間、關聯配對、重點關鍵字與門檻都在 `gfd/config.py`。

- 龍頭股名單是大型權值股觀察清單，不是即時市值排名。
- 新聞重點：標題命中關鍵字 +2、鉅亨關鍵字命中 +1、鉅亨頭條 +2、提及龍頭股 +1（最多 +2）、標題提到當日異常波動的標的 +2；分數 ≥ `HIGHLIGHT_SCORE`（目前 7）標為重點。
- 異常波動：當日變動 ÷ 近 60 個交易日變動的標準差，絕對值 ≥ `MOVER_Z`（目前 2）。

## 價格口徑（哪個數字是什麼）

- **「收盤」只採用已收盤的價格**：交易時段還沒結束的市場（24 小時交易的外匯、期貨、VIX）顯示前一次收盤／結算，並標出日期；判斷依據是鉅亨 `session` 與 Yahoo `currentTradingPeriod`。
- **台股漲跌以證交所基準價計算**：除權息日用「除權除息計算結果表」的開盤競價基準，不是前一日收盤（例：台積電 2026-09-16 除息 7 元，收 2,380 為平盤），並在列上標註「除息 x 元」。
- **各分頁最上面的大數字卡片**＝最新已收盤價＋日漲跌（和鉅亨每日頁同一份數字）；12 個月漲跌用週線計算；30 年位階用研究用月資料。只有月資料的序列（例：台灣重貼現率）會標「月資料」。
- **研究用月資料**（折線圖、關聯、統計表）的當月數字是月初至今，每天更新；匯率與商品是月均值。
- 期貨收盤取 Yahoo 定稿後的日線（約台北中午後定稿），所以 07:30 那次匯入的期貨會是前兩天的結算價，18:30 那次才更新成前一天。
